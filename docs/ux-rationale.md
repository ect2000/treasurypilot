# UX rationale

Overview answers: available authority, remaining reserve, autonomy and the next obligation. Provider wallets appear separately so unallocated millions cannot imply permission.

Plan compares prior/current revisions and highlights only reopened rows. Inspectors explain reasons, assumptions, dependencies, corridor and approval requirements. Delay changes authority; settled receipt allocation changes liquidity.

Evidence separates untrusted text, reviewed facts and real historical deposit proof. Allocation explicitly cannot repeat the deposit. Approval requirements remain planning-only outside the fixed supplier campaign; historical fulfillment is shown without inventing an approval.

Reconciliation places expected/observed/variance alongside status. Incidents investigate the original payment and block duplication. Cash position derives current/target/gap and indicative movements. Audit exports actual persisted events and provenance.

Free-model failure visibly activates deterministic extraction. Revision conflicts/storage uncertainty stop actions. No fabricated deposit, balance update, processing animation or optimistic financial success is used.
